## 1. 프로젝트 개요

- 앱: **퉁(Toong)**. 가입 없이 방 코드·링크로 모인 친구들이 메뉴별로 비용을 나누고 결제자끼리 상계해 최종 송금액을 보는 Flutter 정산 앱.
- 과목: 교수님께 6주 동안 주차별로 진행을 보고하는 프로젝트.
- 저장소: `skngyj/toong`. 작업 브랜치 `claude/kind-darwin-6zhjjp` → PR로 `main`에 합침.
- 서버: Supabase 프로젝트 `qdytkjgqiugdezgwptgw` (Postgres + RLS + 보안 정의 RPC, 익명 로그인, pg_cron, Edge Function `scan-receipt`).
- 영수증 인식: Gemini API `gemini-3.5-flash-lite` (무료 등급). 키는 Supabase 비밀 값 `GEMINI_API_KEY`에만 있음(사용자가 직접 넣음).
- 앱 빌드: `main`에 합칠 때마다 GitHub Actions가 APK를 만들어 Releases `build-N`에 올림(`toong.apk`). 서명 키가 고정되지 않아 새 빌드 설치 전 기존 앱 삭제 필요(기록·가계부도 지워짐).

## 3. 지금 앱에 있는 기능 (main 기준, PR #13까지)

- **방**: 생성, 방 코드 입장, `toong://join/코드` 링크 입장, 참여 중인 방 목록, 방장 방 삭제(목록의 휴지통).
- **인원**: 방장이 `사람 추가`(앱 없는 친구도 이름만, "미연결"로 들어감)·참여자 칩 ×로 빼기. 방장·지출에 들어간 사람은 못 뺌, 이름 1~12자, 같은 이름 불가, 30명까지. 추가한 사람은 나중에 `과거 참여자 기록 연결`로 합침.
- **지출**: 직접 입력, 영수증 촬영·사진 선택(Gemini), 할인 비율 분배, 총액 비교, `모든 항목에 모두 선택`.
- **잔돈**: 직접 지정 또는 `추첨으로 정하기`(후보 선택·`모두 선택`, 2.4초 룰렛, 결과 방에 저장).
- **정산 결과**: 송금 카드마다 오른쪽 동그라미로 **송금 완료 체크**(표시·해제 모두 확인 질문). 보내는 사람·받는 사람·방장만 체크. 모두에게 같은 표시, 금액이 바뀌면 다시 확인 안내. 체크는 삭제 시간을 늘리지 않음. 얼린·완료된 방에서도 가능.
- **방 보관**: 48시간 무입력 삭제, 연장 3회, 얼리기(동시 2개, 7일), 정산 완료 후 12시간 뒤 삭제.
- **정산 완료**: 미체크 송금이 있으면 한 번 더 확인 → 출력기에서 영수증이 "지지직" 나오고 "탁" 뜯기는 애니메이션(진동). 이 정산서에는 ✓ 표시 없음. `영수증 이미지 저장` 가능.
- **정산 기록**: 기기에만 저장. 영수증 모양 "퉁 정산서"(보낼 돈·지출 내역·개인별·총액·바코드·정산완료 도장, 체크한 송금은 ✓). `영수증 이미지 저장`(PNG를 사진 앱에, 파일명 `퉁_방이름_날짜`), `글자로 복사`.
- **가계부**: 시작 화면 `내 가계부`. 정산 완료 시 내 부담액을 지출 한 건당 한 줄 자동 기록(방마다 한 번), 직접 기록, 월별·분류별 합계, 월 예산 80%·100% 알림. 기기에만 저장.
- **디자인**: 흑백 테마(`lib/theme.dart`), 홈 로고(4조각 '퉁'), 앱 아이콘(위아래가 찢긴 흰 영수증 위 4조각 '퉁', 배경 `#222222`), 확인 창은 **확인 왼쪽(검정)·취소 오른쪽(빨강)**, 하단 내비게이션 바 여백.

## 4. 주요 결정과 이유

- **서버 저장 최소화**: 완료 기록·가계부는 기기에만. 사진·인식 결과는 서버에 저장하지 않음(하루 호출 횟수만).
- **CLOVA → Gemini**: 가장 큰 이유는 비용.
- **메뉴판 인식 제외**: 구현해 시험했으나 휴대폰 실사용에서 실패율이 높음(무료 등급 `flash-lite` 503 과부하). `gemini-3.5-flash`는 무료 등급에서 **앱 전체 하루 20회** 한도와 25초 초과 응답으로 사용 불가. 앱·서버 코드에서 모두 삭제. **4주차 보고서에 제외 결정으로 적기로 함**(3주차 보고서는 "제외 고려 중"으로 둠).
- **Gemini 503 대응**: 서버가 1.5초 뒤 한 번 재시도. 무료 등급 과부하는 완전히 막을 수 없음.
- **영수증 사진 보기**: 요청했다가 취소(서버 사진 저장 안 하는 원칙 유지).
- **영수증 테마 전체 UI 시안**: 보류. 대신 흑백 기본 디자인 + 정산 기록만 영수증 모양.
- **잔돈 추첨 연출**: 가챠(룰렛) 먼저, 사다리타기는 추후.
- **로그인 안 함**(4주차 논의): 장점(재설치·기기 변경 시 유지, 공유 구독)보다 장벽(서명 키 미고정이라 카카오·구글 로그인 불가, '가입 없이' 핵심과 충돌, 개인정보처리방침·계정 삭제 의무, iOS Apple 로그인 의무, 일정)이 커서 익명 로그인 유지. 닉네임·계좌는 기기 저장, 정기 구독도 기기 저장.

## 6. 4주차 계획 (사용자 확인 대기: "이 계획으로 시작할까요?")

교수님 피드백(오늘) + 다음 주까지 할 일. 결정된 선택 포함.

| 순서 | 할 일 | 정한 방식 |
| --- | --- | --- |
| 1 | 방장이 추가한 인원의 "미연결" 표시를 빨간 글씨로 | 칩의 "미연결"만 빨강 · **완료** |
| 2 | 얼리기·녹이기 UI | 남은 시간 상자에만: 얼리면 서리·얼음 결정·광택·눈송이, 녹이면 물방울·따뜻한 주황빛, 진동 · **완료** |
| 3 | 방 코드 입장 제한 | **보류**: 사용자가 다른 방식으로 구현 예정 |
| 4 | 방 입장 QR | 방 코드 옆 `입장 QR 보기`(가운데 로고, `toong://join/코드`), 입장 화면 코드칸의 `QR 스캔`(코드만 채움, 입장은 직접) · **완료** |
| 5 | 잔돈 추첨 확률 설정 | 돌림판(칸 크기=확률)으로 바꿈, `확률 직접 정하기`로 후보별 비율 1~10·% 표시, 정한 확률은 `remainder_odds`로 방에 저장해 정산 결과(빨간 글씨)·정산서·기록 글에 표시. 서버 변경 없음 · **완료** |
| 6 | 영수증 가림 대응 | 서버가 가려진 줄도 빈칸(null)으로 남김(scan-receipt v8). 이름 가려지면 "메뉴 N"+빨간 칸, 금액 가려지면 빈 빨간 칸(하나뿐이면 총액으로 계산해 주황 안내), 읽지 못한 칸 수 안내, `차액을 항목으로 추가`, 하나도 못 읽으면 다시 찍기 · **완료** |
| 7 | 계좌 등록 + 은행 앱 열기 | 방 만들기·입장 때 `송금받을 내 계좌 (선택)`(기기에 저장해 자동 채움), 방에서 참여자 칩/`내 계좌 등록하기`로 수정(본인, 미연결은 방장). 정산 결과에서 **보내는 사람에게만** `송금하기` → 계좌·금액 복사, 은행 앱 23개 중 골라 열기(없으면 Play 스토어 검색), 돌아오면 송금 완료 질문. 서버 `set_toong_account`, 정산서·기록에는 계좌 없음 · **완료** |
| 8 | 정기 구독 정산 | 시작 화면 `정기 구독`. 기기에만 저장. 이름·금액·결제일(없는 달은 말일)·알림 시각(시·10분 단위 직접)·전날 알림, 함께 쓰는 사람·결제자·나, 똑같이(잔돈은 결제자) 또는 직접 금액, 결제자 계좌. 앞으로 12달 치 로컬 알림 예약(앱 열 때 다시 채움, 재부팅 후 유지), 알림 누르면 구독 화면. 이번 달 보낸 사람 체크·지난 달 기록·요청 글 복사·송금하기·알림 미리 보기. 결제일 지나면 내 몫을 가계부 `구독`에 달마다 한 번 · **완료** |
| 9 | 본인 닉네임 저장 | 방 만들기·입장 성공 시 기기에 저장, 입장 화면·구독 "나" 자동 채움. QR·링크는 닉네임이 있으면 "○○(으)로 입장할까요?" 한 번 뒤 바로 입장. 시작 화면 시간별 인사(5~11시 아침, 11~17시 점심, 그 밖 저녁)와 닉네임 정하기·바꾸기·지우기. 이미 들어간 방 이름은 안 바뀜. 로그인 없음 · **완료** |
| 10 | UI가 재미없다(교수님) | `lib/fun.dart`. 송금 체크 시 빨간 "송금완료" 도장 쿵, 마지막 송금 체크 시 "정산 끝!" 띠+종이 조각(정산 결과 위쪽 영역만), 정산 완료 영수증 주변 종이 조각, 금액 숫자 굴러가기(함께 쓴 금액·송금액·가계부), 주요 버튼 눌림+진동, 새 지출 카드 떨어지듯, 빈 화면 영수증 그림, 부드러운 화면 전환(Android), 첫 실행 때만 로고 4조각 모이기. 방 코드 슬롯머신은 투머치라 뺌. 휴대폰 "애니메이션 줄이기" 존중 · **완료** |

## 8. 작업 방식 (사용자 선호)

- 큰 작업은 **계획을 먼저 보고**하고 "진행해줘"를 받은 뒤 시작.
- 마무리는 **"PR 만들어서 충돌 확인 후에 합쳐줘"** → PR 생성 → mergeable 확인 → merge → 작업 브랜치를 main에 맞춤 → 빌드 링크 안내.
- 비밀 값(키)은 채팅에 붙이지 않고 사용자가 직접 Supabase·GitHub Secrets에 넣음.
- 디자인은 시안 이미지(캡처)를 보여주고 고르게 함.
- 답변은 한국어, 쉬운 말.

## 9. 테스트·검증 방법

- 앱: `dart analyze lib test`, `flutter test`(현재 60개 통과). Flutter SDK는 `/opt/flutter-sdk/flutter/bin`.
- 서버 함수: `node --experimental-strip-types --test supabase/functions/scan-receipt/receipt.test.ts`(4개).
- SQL: 로컬 PostgreSQL 16(`/tmp/pgt`, 포트 54329, stub auth/cron)으로 마이그레이션 전체 적용 후 테스트. 서버 시작:
  `su postgres -c "/usr/lib/postgresql/16/bin/pg_ctl -D /tmp/pgt/data -l /tmp/pgt/log -o '-k /tmp/pgt -p 54329' start"`
- 실제 서버 확인: Node로 익명 가입 후 RPC 호출(`NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt`), 시험 방은 지움.
- 화면 확인: 테스트에서 한글 글꼴(wqy-zenhei)을 불러와 골든 캡처를 찍어 확인(커밋하지 않음).
- 주의: 이 환경의 스크래치 폴더와 로컬 DB는 세션이 끝나면 사라질 수 있음.
